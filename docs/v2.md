# v2 score

The comparable score is one harness force-call count per start, reduced by PAR-2, a Wilson interval, and a bootstrap median. The 2014 half-even mean stays on the archive tables and is labelled legacy. This note is the spec for the pieces the score needs: one counter for every client, repeats over seeds, failure classes, and additive force noise.

`docs/design/decision.md` is why PAR-2 is the ranking cell. `docs/harness.md` is the in-process wrapper and the quadratic smoke.

## One counter

`HarnessCounter` is the tally. A force call is one entry that asks for the energy and the gradient. An analytic Hessian-vector product used in the search costs one force call, the same as one forward-difference product: the gradient at the current point is already counted, and the displaced gradient is one more entry. A full analytic Hessian costs one such product per coordinate. The index Hessian is verification. It increments `verify_calls` and is not a search call. The problem files do not define a separate analytic-Hessian score.

In-process wrappers cache a second request at the same coordinates. An energy read and a force read of one geometry are one evaluation. `CountedPotential` does that for `evaluate(coords) -> (energy, gradient)`. `attach_ase_counter` counts ASE `calculate` entries, which ASE already skips when the geometry is unchanged. `PeleCounter` counts `getEnergyGradient`, and `getEnergy` goes through that method.

A compiled client is not wrapped by those objects. It reaches the same counter from outside the process.

- eonclient uses its `ext_pot` potential. eOn writes `from_eon_to_extpot` (three box rows, then `Z x y z` rows) and runs `ext_pot_path`. `python -m optbench.extpot` reads that file, sends one `calculate` to the counting server, and writes `from_extpot_to_eon`. `OPTBENCH_POTSERVER` is `host:port`. One `force()` in the client is one connection.
- rgmin and rgsaddle call an rgpot `calculate(positions, atomic_numbers, box)`. `RgpotCounter.calculate` is that shape on a `HarnessCounter`. The socket server uses one `RgpotCounter`, so a socket request and an in-process rgpot call share the tally when they are given the same counter.

The server binds `127.0.0.1` on an ephemeral port. The dialogue is text, one command per connection:

| Command | Request | Reply |
| --- | --- | --- |
| `calculate` | atom count, nine box floats, one `Z x y z` line per atom | `ok`, search calls, verification calls, energy, one `fx fy fz` line per atom |
| `reset` | | `ok` |
| `count` | | `count`, search calls, verification calls |
| `verify` | `on` or `off` | `ok` |
| `bye` | | `bye` |

A failed command replies `error` and `ClassName: message`. The server counter does not cache. The client decided to call `force`, so a repeated geometry counts again. That is the comparison with eonclient's `total_force_calls`.

A search call once `calls` has reached the cap raises `ForceCallCap` before the potential runs. The refused call is not counted, so the recorded tally is the cap and the run is the cap failure. The ext_pot ini sets `Main.parallel` false. `ExtPot` otherwise takes a new instance per image, and a saddle-search `total_force_calls` stores only the primary counter. Rotation and forward-image evaluations are real `force()` calls. One instance puts them in the field the harness is compared with.

`uv run optbench run` is unchanged. It still shells out to the client's own potential and writes `counter` `client` with `comparable` false. That file is not a v2 score.

### Lennard-Jones check

`ljcluster` in the eonclient templates is rgpot `LJClusterPot`: `u0 = 1`, `psi = 1`, cutoff 15, free boundary, pair energy shifted so the cutoff is zero. Pairs at or beyond the cutoff are left out. `optbench.lj.lj_cluster` is that kernel. The problem cutoff of 40 is not what `templates/eon-client/lbfgs-m100.toml` sets.

```bash
uv run optbench validate-counter --limit 3 --output results/validation/lj38-counter.dat
```

The command runs the first geometries in sorted order from the LJ38 archive, twice, with template `eon-client/lbfgs-m100` (L-BFGS memory 100, force norm 0.01, iteration cap 10000). One run is the client's `ljcluster`. The other is `ext_pot` into the counting server. The harness count has to equal `total_force_calls` in the ext_pot `results.dat`. The built-in `ljcluster` count is recorded beside it. Those two counts are the same when L-BFGS walks the same path. The ext_pot reply is text, so the forces that re-enter the client are not the bitwise values `ljcluster` kept internally, and a later start can take a different number of steps or finish in a different basin. That difference is recorded. It is not a second counter. The dat, the per-start JSONL, and the copied client `results.dat` files are the run. `published_mean` is false. A published LJ38 mean uses all 1000 starts.

The dat records `code_version` and `commit` from `eonclient --version`. The registry commit for a published eOn score stays `4d8b34baf1ba8d2d980df29838bac1f969d1662c`. The short token printed by a conda-forge binary is the token that binary embeds.

rgmin and rgsaddle are not run here. They are not on conda-forge and this tree has no release binaries. The counter they would use is `RgpotCounter.calculate`.

## Seeds

A displacement sample adds an independent `N(0, sigma^2)` shift to each coordinate. `sigma = 0` copies the point and does not draw. A dimer orientation is a normal vector normalised to unit length. Start `index` uses `random.Random(seed + index)`.

The quadratic bowl and saddle in `optbench.smoke` are the sample, not Lennard-Jones. Displacement is gradient descent, step 0.05, cap 5000, `sigma = 0.02`, 8 starts, seed `20261016`, from `(0, 0)`. The dimer sample rotates a mode in the plane until neither neighbour has a lower curvature, then translates along the effective force that reverses the component along the mode. It uses 8 orientations, `sigma = 0.05`, cap 500, from `(0.4, -0.3)`.

Every start stays in the PAR-2 mean. The report is that mean, the median and its percentile bootstrap interval, and the Wilson 95% interval on the success rate. The bootstrap for this sample uses 200 resamples when `optbench.statistics` builds the profile and the noise rows, so the sample stays small. `score_v2` itself still defaults to 2000 resamples and seed `20261015`. The seeded displacement and dimer rows use that default, through `summarise_run`.

The measurements are asv tracks. `benchmarks/quadratic.py` calls these same functions, with `param_names` `seed` and `start`. `track_force_calls` stores the harness count (unit `force calls`). `track_success` and `track_failure_*` store the success bit and the failure classes. Saved asv files carry `track_failure_cap`, `track_failure_wrong_stationary`, `track_failure_divergence`, and `track_failure_crash`. `not_converged` is absent from those files. A reader treats a missing track as no class bit, and campaign records are rescored from the stored energy, geometry, force, and call count. `time_search` is the wall time. `uv run optbench statistics` reads `results/asv` and scores those tracks. It does not run the optimizers again. A saved `asv run` feeds that command. `--quick` is only a smoke gate, and on asv 0.6.6 it still rewrites the result file. The layout, the pin, and the way to add a code are `docs/asv.md`. What asv does not store is `docs/asv-gaps.md`.

```bash
uv run asv run COMMIT^! -b quadratic
uv run optbench statistics --output results/validation/statistics.json
```

The file is a smoke sample. It is not a campaign mean.

## Performance profile and PAR-2

The Dolan-Moré profile is the fraction of problems whose cost is at most `tau` times the best finite cost on that problem. `tau` is `1, 2, 4, 8, 16`. An unsolved problem has an infinite ratio. It stays in the denominator and does not cross a finite `tau`. `solved` is the fraction of finite ratios. `area_log10` is the trapezoid integral of the profile against `log10(tau)`.

The profile cost of a success is the harness force-call count. A failure is infinite there. PAR-2 is a different summary of the same starts: a failure costs `2 * cap`, and the mean includes it. The profile is not the ranking cell.

The sample compares three gradient descents on five bowl starts (the origin and four normal draws, seed 11, scale 0.05): step 0.05 with cap 5000, step 0.01 with cap 20000, and step 0.001 with cap 30.

## Failures

A start has one primary class. `optbench.failures.classify_outcome` is the only decision. It reads the final energy, the geometry, the true force, and the call count. A runner-reported class string is not an input. The first match wins.

1. `divergence` — the energy is `+inf`, `-inf`, or NaN, or the geometry blows up. A blow-up is a non-finite coordinate, a dissociation, or a maximum atom displacement strictly above a bound the problem states. A finite energy and a finite geometry are not a blow-up.
2. `cap` — the force-call count is at or above the harness cap. A LAMMPS NEB band that ends on `max iterations` or `max force evaluations` on every replica is this class only when that count has reached the harness cap.
3. `crash` — the process failed, and the energy and the geometry stayed finite and under the cap.
4. `not_converged` — the process finished, nothing blew up, the cap was not hit, and the true force is still above the tolerance. A method that stops on its own residual or its own step limit is this class. A finished band is this class when the judged image, the climbing image or the highest image of a plain NEB, still has a finite force above the problem stop. A plain NEB has no climbing image, so that stop is not a saddle. A LAMMPS NEB band whose every replica last stopped on `max iterations` or `max force evaluations`, with a finite climbing-image force still above the stop, is this class when the call count is still under the harness cap. A force equal to the tolerance is not above it.
5. `wrong_stationary` — the force is at the stop and the point is rejected: the Hessian index is not the one the problem asks for, or the energy, the Kabsch RMSD, the link, the novelty test, or the barrier rejects it. A stopped band whose Hessian index is not 1, with the force already at the stop, is this class.

The 2014 paper and the archived OptBench site do not name these tokens. They report `nfailed`. The site says a run fails when it exceeds the maximum number of force calls or fails to converge for any other reason. The NEB section calls the second case a failure to converge. `cap` is the first clause. `not_converged` is that second clause when the energy and the geometry stayed finite and the harness cap was not hit. The paper has no separate token for it, so the harness name is that clause and it is not `divergence`. A non-finite energy or a blown geometry would also sit inside the paper's "fail to converge for any other reason"; the harness keeps that event as `divergence` because it is not a residual stop. `wrong_stationary` is the archived transition-state failure in which the force stop is met and a positive zero eigenvalue, or the wrong index, rejects the point. A converged saddle that fails the link, the novelty test, or the barrier is the same class. `crash` is a process that returns no result. The paper would count it as a failure for any other reason. It is not a convergence decision.

On Lennard-Jones 38 the Hessian index is vibrational. The cluster is free, so the three translations and the three rotations about the centroid are removed before the count. Those rotations are an exact kernel only at a true critical point. At the force stop of 0.01 their Rayleigh quotients sit around `1e-4` and can be negative; counting them with a fixed cutoff of `1e-6` marks a minimum as a saddle. After the projection, a curvature is negative only when it is below `-max(force_norm, 1e-8 * ||H||_F, 1e-6)`. The force stop is the resolution of the test: a unit displacement along a shallower mode changes the force by less than the stop. `||H||_F` is the Frobenius norm of the Cartesian Hessian. That curvature rule is in the `success` field of `problems/minimization/lj38.toml`, together with one connected cluster: neighbours within 1.5 sigma. A dissociated end state is `divergence`. Morse bulk uses the Morse bond length with the orthorhombic minimum image. The campaign records store energy, and an energy above the spanning-tree ceiling of those contacts is the same failure.

A success stores `failure` as null. `n_cap`, `n_wrong_stationary`, `n_divergence`, `n_not_converged`, and `n_crash` sum to `nfailed`. `includes_failures` is true. `success_only_mean` is the mean of the successes alone, so a dropped failure is visible next to the PAR-2 mean and is not the score.

A non-finite result does not request a Hessian. Verification calls still increment `verify_calls` and are not search calls.

## Noise

Forces gain independent `N(0, sigma^2)` samples. The energy stays the clean energy, so the force is not the gradient of the energy that is stored. `sigma = 0` does not draw.

The documented levels are `0`, `1e-4`, `1e-3`, and `1e-2`. `kappa` is 3. The window is 5 evaluations.

The force-norm stop is `max(clean tolerance, kappa * sigma * sqrt(components))`. When `sigma` is positive the clean energy over the last `window` evaluations must also span at most the energy tolerance. One small force sample does not stop the search. When `sigma` is zero the stop is the clean force tolerance and the window is ignored.

The stationary test uses the clean force. A finite-difference Hessian of the noisy force is not an index. The tolerances for that test are fixed before the run: `energy_tol = max(clean energy tolerance, kappa * sigma)` and `rmsd_tol = max(clean RMSD tolerance, kappa * sigma)`. The force tolerance passed into the start record is the noise-aware stop, so a point that met the floor is not charged with `force_norm`.

`problems/minimization/lj38-noise.toml` is the Lennard-Jones 38 statement of this rule. Its harness campaigns are the ranked rows for that file. Newton and dogleg use the analytic Hessian of the clean force, so they are recorded only at sigma 0. The measured noise rows in `results/validation/statistics.json` are the quadratic bowl.

## Keys a v2 result carries

`optbench.v2.V2_KEYS` is the list. Every problem file has `[scoring.v2].required` equal to that list, and `[scoring.legacy].label` equal to `legacy`.

| Key | Where it sits |
| --- | --- |
| `schema` | start, or the validation document |
| `counter` | `harness` for a v2 score |
| `force_calls` | search calls on that start |
| `success` | the start passed the rule |
| `failure` | the primary class, or null |
| `comparable` | true when `counter` is `harness` |
| `code`, `code_version`, `commit` | provenance |
| `tuning` | `default` or `tuned` when the template says so |
| `par2_mean`, `median`, `median_low`, `median_high` | the PAR-2 summary |
| `wilson_low`, `wilson_high` | the success-rate interval |
| `n`, `nfailed` | starts, and how many failed |
| `n_cap`, `n_wrong_stationary`, `n_divergence`, `n_not_converged`, `n_crash` | the five classes |

`metrics.required` is the 2014 column list. The v2 names are not added there. `optbench check` still compares the oracle with those columns.

Legacy rows keep the caption "Legacy 2014 archive". The label in the problem file is `legacy`.

## hTST

`optbench.htst` scores `problems/hTST`. It reads one AKMC `processtable` and one `search_results.txt`. A barrier window closes when every reference barrier has been matched once, in processtable order, to a `good` or `repeat` result. The force calls in that window are the `sad-fcs` column. A rate window closes when the sum of `prefactor * exp(-barrier / kT)` reaches 0.999 of `rate_ref`. The prefactor is the search row's harmonic prefactor when the row carries one, and the problem constant otherwise. Both 2014 scripts use `1.2e12`.

`harmonic_prefactor` is the eOn `RATE_HTST` product. It takes the square root of the minimum eigenvalues over the positive saddle eigenvalues and divides by `2 * pi * 10.18e-15`. A minimum with a negative mode, or a saddle without exactly one negative mode, returns -1.

The aluminium evaluator named in the problem file is `eam_al`. `optbench.potentials.eam_al` is the rgpot double-exponential kernel, cutoff 7.1 Angstrom, with pairs dropped at `sqrt(0.9999)` of that cutoff. The gradient is dE/dx. Platinum names `morse_pt`, the shifted Morse in `optbench.pes.morse_pt` with cutoff 9.5 Angstrom. That is the eOn `MorsePot` default.

The aluminium template displaces file index 384, the adatom. The 2014 ini wrote `displace_atomlist = -1`. That manual means the last atom. This eOn treats `-1` as every free atom. Platinum displaces the least coordinated atom, as the 2014 ini did.

The eOn 3.6.0 aluminium window mean is 44 jobs and 5.563e3 saddle force calls. The 2014 `eon-dimer-cg` mean is 48 jobs and 2.887e4. Both means sum `sad-fcs`. `mins-fcs` is the minimisation column. Its median is 117 on the 30997 searches in the 2014 log and on the 28604 searches in the 3.6.0 log. Both runs use the eight reference barriers below 0.4 eV. The 3.6.0 dat has `missed_barriers 0`.

`repeat` rows have `sad-fcs` median 280 in the 2014 log and 75 in the 3.6.0 log. `Not Connected` is 6221 of 30997 searches in the 2014 log, median 827, and 5298 of 28604 in the 3.6.0 log, median 163. The same 3.6.0 client with `improved` false, `rotation_backend` classical, seed 42, adatom 384, angle tolerance 1, rotation cap 50, and the scored force stop, over 204 searches, has a `repeat` median of 228.5 at `finite_difference` 0.001 and 231 at `finite_difference` 0.01. `Not Connected` is 137 of 204 and 125 of 204. Classic rotation in this client stops on torque, `torque_min` 0.1 and `torque_max` 1. The classic loop does not read `converged_angle`. With `improved` true and `finite_difference` 0.01, 204 searches give a `repeat` median of 73 and `Not Connected` on 41 of 204. `convergence_metric` `norm` with the other scored settings, 208 searches, gives a `repeat` median of 87 and a `repeat` minimisation median of 139. The scored `max_atom` run is the one whose minimisation median matches the 2014 log.

`Dimer.cpp` evaluates the rotational force twice on a rotation that has not converged. `ImprovedDimer.cpp` evaluates one trial force and interpolates the forward gradient. The 2014 ini leaves `improved` unset. The 3.6.0 default is true, and the aluminium template sets true. That rotation is the lower saddle count on the scored row.

A board start is one completed barrier window. The v2 rank is the median of those `sad-fcs` totals. PAR-2 stays unset when the problem file gives no force-call cap. `barrier_jobs`, `barrier_force_calls`, `rate_jobs`, and `rate_force_calls` are the 2014 means: jobs truncated toward zero, force calls printed with `%.3e`. A run whose distinct saddle rates stay under `rate_ref * 0.999` records no rate window. The barrier windows are still scored.
